# Linux distribution options (x86_64 only)

Slick is BYOE: install the **official Slack** first. No Slick package may redistribute Slack's `app.asar`. The existing installer and release tarball remain available; the options below are not published yet. GitHub release build attestations cover the downloaded assets, but package-manager signatures need their own trust setup.

| Channel                               | Initial effort | Ongoing maintenance                                                                                         | Secrets                                                                                 | Recommendation                                                                    |
| ------------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| AUR `slick-bin`, `slick-git`          | Low            | Update version/checksum per release; watch Slack paths and build deps                                       | None                                                                                    | Start here after a v2 release exists.                                             |

## apt and dnf

Taut's [repository generator](https://github.com/jeremy46231/taut/blob/HEAD/scripts/repo.ts) constructs apt `Packages`, `Packages.gz`, `Release`, signed `InRelease` and `Release.gpg`; it signs RPMs with `rpmsign`, runs `createrepo_c`, then signs `repomd.xml`. Its [RPM repo file](https://github.com/jeremy46231/taut/blob/HEAD/server/public/rpm/taut.repo) advertises its hosted endpoint at taut.jer.app. Slick's disabled `.github/workflows/linux-repos.yml` sketches metadata generation from `slick_2.0.<build>_amd64.deb` and `slick-2.0.<build>.x86_64.rpm`; these assets are **not** produced by the current release workflow. Before enabling it, sign both the apt metadata and RPM packages/metadata, publish a public key and installation instructions, verify imported keys and packages in clean distro containers, and add an atomic deployment to Pages or R2. Pages can serve static `dists/`, `pool/`, and `repodata/`; R2 needs custom-domain and cache invalidation policy. Do not put private keys in the repository; use protected secrets and a restricted publishing identity. The scaffold deliberately uploads only an unsigned preview artifact and cannot run until explicitly enabled.

## AUR

`packaging/aur/slick-bin/` contains a release-tarball PKGBUILD that fetches its desktop file and icon from the matching source tag. Replace its placeholder version and SHA256 values with the first actual v2 release's digests, then regenerate `.SRCINFO` using `makepkg --printsrcinfo > .SRCINFO` before submitting. `packaging/aur/slick-git/` builds from Git and packages the electron-builder tarball; refresh its `.SRCINFO` too. The `slack` dependency refers to the separately installed official Slack AUR package. Neither package is submitted or installed by this work. AUR build downloads from GitHub/npm are inherently networked; verify source and artifact hashes before publication. The rolling package's Electron download is controlled by electron-builder's own build process. On Arch, run `namcap PKGBUILD` and `namcap` on the built package where available.

## Flathub

The current [manifest](../packaging/flatpak/dev.slick.Slick.yml) uses a local `dir` source and an Electron zip, so it is not a reproducible remote submission: replace the directory source with a pinned upstream archive plus hashes, vendor or provide verified offline Node dependencies, and pass Flathub's build/test requirements. Its `--filesystem=host-os:ro` / host `/opt` access to a separately installed proprietary Slack `app.asar` is central to BYOE but may not be approved; review Flatpak filesystem portal policy with Flathub before submitting. Document that Slack is installed on the host, that this Flatpak does not bundle it, and that sandbox paths must continue to match Slack's location. The existing metainfo, icon and desktop file are starting points, not approval.

## Nix

The flake builds from source using a fixed-output `bun install --frozen-lockfile --ignore-scripts` result pinned from `bun.lock`; this keeps Nix and normal builds on one lockfile. Nix supplies Electron separately, and no Slack binaries are bundled. `nix run` launches Slick, and users can override the package's optional `slackPackage` argument in an overlay to select `${slack}/lib/slack/resources` explicitly. Nix-store installs cannot self-update; update the flake instead.
